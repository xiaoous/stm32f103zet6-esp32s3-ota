# 按键触发安装 + 流水灯（设计与取舍记录）

> 本文最初是一份"改造方案"（含 `'R'` 请求字节、长按 1 秒检测、三段状态机）。
> 实现过程中方案被简化，这里保留**最终实现**与**为什么放弃原设计**，原始方案见文末附录。

## 一、最终实现

| 组件 | 位置 | 说明 |
|---|---|---|
| 流水灯 | `app_update.c:737 App_led_poll()` | 200 ms 交替 PB5 / PE5，`HAL_GetTick()` 驱动，零阻塞 |
| 按键中断 | `app_update.c:657 HAL_GPIO_EXTI_Callback()` | PE3 下降沿，**只置标志** `s_key_install = 1U` |
| 安装执行 | `app_update.c:674 App_update_try_install()` | 校验元数据与向量表 → 置 24C02 → 复位 |
| 主循环接入 | `app_update.c:828` | `s_session == 0` 时才响应按键 |
| 下载落盘 | `app_update.c:332` | 只写 W25Q128，打印 `push KEY1 to install` |

### 两段式流程（关键设计）

```
ESP32 下载 ─→ CRC32 校验 ─→ 写 W25Q128 ─→ 写元数据 ─→ 打印 "push KEY1" ─→ 回 'A'
                                                                    ↓
                                          板子继续跑老程序，两灯恢复流水，断电安全
                                                                    ↓
                                              按 PE3 ─→ 校验 ─→ 置 24C02 标志 ─→ 复位
                                                                    ↓
                                              P02 看见标志 → 擦除 → 搬运 → 跳转
```

**为什么必须分开**：24C02 的标志位是 P02 判断"要不要装"的唯一依据，一旦置位就无法回退。
下载动作（会失败：CRC、W25Q 坏块、断线）不应该和"覆盖正在运行的程序"绑在一起。
分开后，下载失败或下错了固件，板子依然运行原程序，可以重下。

## 二、放弃的原设计

| 原方案 | 最终实现 | 原因 |
|---|---|---|
| 长按 1 秒检测（软件计时消抖） | EXTI 下降沿单击 | `gpio.c:61` 已配 `GPIO_MODE_IT_FALLING`，硬件出边沿，软件不必再计时 |
| 状态机 FLOW / REQUEST / UPDATE | `s_session` + 一个按键标志 | 只有两个状态，三段状态机是过度设计 |
| STM32 每 1 s 发 `'R'`(0x52) 请求 S3 开始传，最多 60 次 | **不做** | 安装完全在 STM32 本地完成，不需要 S3 参与；S3 仍按自己的流程推包 |
| S3 侧 `ota_proto_wait_request()` 等待循环 | **不做** | 同上 |

## 三、实现时必须遵守的三条约束

1. **ISR 里不能调 `HAL_Delay()`** —— `EXTI3` 优先级 4 高于 SysTick 的 15，中断里等 tick 会永久挂死。回调只置标志，重活放主循环。
2. **主循环不能阻塞超过约 150 ms** —— 115200 下 2048 字节帧耗时 178 ms，环形缓冲只有 2304 字节（`APP_OTA_RING_SIZE`）。任何 `HAL_Delay(200)` 都会灌满缓冲丢帧。所以流水灯必须是 `HAL_GetTick()` 比较式。
3. **升级中两灯全灭** —— `s_led_quiet` 边沿判定，进入会话立即一次性关灯，避免每帧重复写 GPIO。

## 四、按键路径的安全闸门

`App_update_try_install()` 在置标志前做足校验，因为 **P02 装完后只校验栈顶与复位向量，不校验内容**，坏镜像会被当真装进去：

| 检查 | 期望 |
|---|---|
| 元数据 `start` | `>= 0x001000` |
| 元数据 `size` | `512 <= size <= 0x78000` |
| 镜像前 4 字节（栈顶） | `& 0xFFFF0000 == 0x20000000` |
| 镜像 4-8 字节（复位向量） | `0x08008000 <= rvec <= 0x08080000` |

任一项不过：只打印原因，**不置标志、不复位**，回到流水灯。

## 五、已知风险

- **单次安装**：装完 P01_led2 后它不含 OTA 代码，按键与串口接收都不再生效，只能 Keil 重烧。
- **P02 侧不校验元数据**：`App_bootloader.c:128` 忽略了 `App_bootloader_check_meta_data()` 的返回值，`:133` 仍按 `app_size` 擦页。空白 W25Q 会得到 `app_size = 0xFFFFFFFF`，擦除范围可能越过应用区。app 侧的校验是目前唯一的防线。
- **镜像上限 32 KB**：`APP_OTA_IMAGE_BUF` 整包缓存在 RAM，超限会在 START 阶段被拒。

## 附录：原始方案（已被取代，仅存档）

最初设想：上电跑流水灯 → 长按 1 秒 → STM32 通过 USART2 每 1 s 发单字节 `'R'`(0x52) 请求 ESP32 开始传包，最多 60 次 → 传输 → 自动安装。四段状态机 FLOW / REQUEST / UPDATE 管理。
放弃原因见上表：安装是纯本地动作，不需要跨板协商。
